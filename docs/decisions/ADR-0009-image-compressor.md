# ADR-0009: Browser Image Compressor

- **Status:** Accepted for TBX-009.
- **Scope:** Compress one JPEG, PNG, or WebP image per run. No upload service, server processing, persistence, or generalized image-job framework.
- **Validation ownership:** `core/image-input` owns reusable JPEG/PNG/WebP signature/structure checks. `core/image-compressor` owns compressor-specific one-file, byte, side, pixel, format, and output limits. `contracts` validates file metadata and strict output format/quality.
- **Processing:** `browser-engines` uses `createImageBitmap({ imageOrientation: "from-image" })`, Canvas drawing and `convertToBlob()`/`toBlob()`. It verifies requested MIME, output signature, dimensions, and byte ceiling before success. Native browser support is checked by the actual returned Blob; when an encoder falls back to PNG or fails, the tool reports the unsupported output format rather than relabeling bytes.
- **Format behavior:** JPEG/WebP accept quality 10–95 (default 80). PNG encodes decoded canvas pixels losslessly and has no quality control; it may grow. JPEG fills white before painting, so transparent input has an explicit white background. PNG/WebP keep alpha. Orientation is baked into output pixels; source EXIF/ICC metadata is removed or may be transformed by browser color handling. This is not archival color management.
- **Resource bounds:** One file up to 16 MiB, at most 8 MP and 8,192 px per edge, output at most 24 MiB, and a 30-second operation watchdog. One 8 MP RGBA bitmap is roughly 32 MiB. The bitmap and canvas may coexist (~64 MiB of pixel backing), in addition to compressed input, encoded output, and browser codec allocations. These caps reduce resource pressure but do not guarantee survival on every low-memory device; native codec peak memory was not measured.
- **Cancellation and cleanup:** The UI terminates its dedicated worker, aborts its page-side canvas fallback, ignores stale generations, closes each `ImageBitmap`, sets temporary canvas dimensions to zero, and revokes preview/result URLs on replace, reset, or unmount. A browser-native encode already dispatched on the main-thread fallback cannot be synchronously interrupted; its result is discarded and cleanup runs when its callback settles.
- **Browser compatibility:** Prefer worker `OffscreenCanvas` when its 2D context is available; otherwise request one sequential page-side canvas operation. If the requested encoder is not supported in that browser, explain the failure and allow another format. Chromium and WebKit are tested. Physical Android/iOS memory behavior and device-native codecs are not established by Playwright.
- **Dependencies:** No application dependency was added. Browser Canvas APIs avoid shipping a second codec implementation and its bundle/license/maintenance cost. A codec library would only be reconsidered if browser output support proved insufficient; the alternative today is a clear format-specific failure, not an unverified polyfill.
- **Privacy:** Inputs, outputs, names and sizes are not sent to the server or analytics. Downloads use the generic name `toolbox-image.<extension>`.
- **Publication:** Only `image-compressor` may change from draft to published after binary tests, Chromium/WebKit, standalone build and shared CI validation pass. Other draft statuses remain unchanged.
