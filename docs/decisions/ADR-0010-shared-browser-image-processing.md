# ADR-0010: Shared Browser Image Processing for TBX-009–012

- **Status:** Accepted for TBX-010; extend only when TBX-011/012 need the same operations.
- **Context:** Compressor and resizer both need signature validation, bounded decoding, EXIF normalization, Canvas output checks and deterministic resource cleanup. Copying those algorithms would make format and limit behavior drift. A generalized image job framework or separate native codec would add dependencies and ownership without a concrete use case.
- **Decision:** Keep file/container parsing and pure image limits in `packages/core`; keep metadata/options schemas in `packages/contracts`; expose small browser operations from `packages/browser-engines/src/image-processing.ts`; keep each tool's geometry, settings, UI and worker contract in its own module. Shared functions use native `File`, `ImageBitmap`, Canvas and Blob APIs and have no Node, backend or UI dependency.
- **Memory lifecycle:** Inspect encoded headers before decoding. After drawing to the bounded output canvas, release the input bitmap and zero canvas dimensions before decoding the encoded Blob independently. Enforce encoded MIME/signature, exact dimensions and output size before returning. Close every decoded bitmap and zero canvas dimensions in `finally` paths.
- **Compatibility:** Prefer `OffscreenCanvas` inside the tool worker. If a worker cannot create a 2D context, it delegates one raster operation to the page and observes an abort signal. This fallback may briefly occupy the main thread; it does not promise equivalent responsiveness to the worker path. Unsupported browser encoders fail explicitly.
- **Bounds:** One image at most 16 MiB, 8 megapixels and 8,192 px on an edge; output at most 24 MiB; one operation at a time and a 30-second UI watchdog. An 8 MP RGBA image and same-size canvas can coexist at about 64 MiB before codec/input/output allocations. Physical-device peak memory is not established by Playwright.
- **Privacy:** Input bytes and filenames stay in the browser. No upload endpoint, persistence, content telemetry or new runtime dependency is introduced.
- **Consequences:** Native output reflects browser resampling, color management and codec behavior; source EXIF/ICC metadata is not retained. Tool modules remain independently testable and may set narrower limits or formats without changing a universal policy.
