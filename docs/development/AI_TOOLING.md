# AI tooling — TBX-002

## Scope and ownership

Developer tooling is installed per user, outside the pnpm workspace. It adds no application dependency, route, converter, database, authentication or deployment. The repository owns this guide, index exclusions and engineering rules. The developer owns Codex configuration, executable paths, caches, credentials and upgrades.

Use a Skill or MCP only when it helps the current task. Toolbox `AGENTS.md`, module boundaries and `docs/06-DESIGN-SYSTEM.md` take precedence over upstream recommendations. Do not load every Skill for every request. Read official documentation matching the pinned library version before applying generated examples.

### Codebase Memory boundaries

The official Windows amd64 release archive for 0.11.0 was extracted manually; the multi-agent installer and hooks were not executed. Its GitHub release asset SHA-256 was verified as `6eb6beaf261b19e419766e78baf93cbc3cf1c6338cff8fb7c0234859f96d1685`.

Set these registration environment values to absolute paths:

```text
CBM_ALLOWED_ROOT=<Toolbox root>
CBM_CACHE_DIR=<TOOLING>/codebase-memory/cache-toolbox
CBM_WORKERS=2
```

Use a dedicated cache and set `auto_index`, `auto_watch`, `watcher_enabled` and `ui_enabled` to `false` with the installed binary's `config` command. Index Toolbox explicitly using `cli index_repository --repo-path <Toolbox root>`. Confirm exact flags with version 0.11.0 `cli index_repository --help` before using them. Do not expand allowed roots. The tested outside-root request was rejected before scanning the temporary audit directory.

Root `.cbmignore` excludes dependencies, generated output, coverage, browser artifacts, Git internals, `.env*`, private key formats, secret directories, databases and temporary document formats. `.gitignore` excludes local graph directories too. Exclusions are defense in depth: do not put unrecognized secrets inside source files. The verified dedicated cache contains only project `D-Pet` at `D:/Pet`; graph persistence into the repository is disabled.

The initial index contained 388 nodes / 453 edges and found `getPublishedTools` in `packages/core/src/catalog.ts`. It reported one partial CSS parse in `packages/ui/src/styles/globals.css` around Tailwind directives, with zero unusable files. Memory results supplement source review and TypeScript checks. Newer upstream main-branch documentation mentions index limits that 0.11.0 does not support; they were not configured or claimed as enforced.

### Playwright boundaries and Windows limitation

Run Toolbox locally before navigation:

```sh
pnpm run build:packages
pnpm --filter @toolbox/web run dev --hostname 127.0.0.1 --port 3100
```

Only navigate to the local Toolbox development application. The browser uses an isolated temporary profile, no extension/CDP attachment, no personal cookies, and output outside the repository. The origin allowlist is an additional network control; upstream explicitly states that it is not a security boundary and does not validate redirects. Do not treat it as a sandbox or visit production/unrelated sites.

On this Windows installation the full Chromium executable failed with a side-by-side configuration error. The already installed stable Chromium headless shell from the project's Playwright Test browser revision 1248 launched successfully and is pinned in this MCP registration. No system runtime or personal browser was modified. Recheck the executable path after a Playwright browser update.

## Verification checklist

1. Verify `gh --version`, authenticated account, repository permissions and the effective branch rules described in [GitHub workflow](GITHUB_WORKFLOW.md); do not print tokens.
2. Verify Skill discovery through fresh Codex `skills/list`, not just files on disk; preserve the Next.js versioned agent guide.
3. For each MCP, initialize, list tools and exercise the calls in the table. Confirm Codex's configured allowlists after reloading the client.
4. For memory, verify the allowed root, dedicated cache, exclusions and outside-root rejection; inspect any parse warnings.
5. For Playwright, inspect the local page title and landmarks, then close the browser and stop the local dev server.
6. Run `pnpm lint`, `pnpm typecheck`, `pnpm test` (unit tests plus Chromium/WebKit smoke) and `pnpm build`; record results in the PR. No check may be weakened to pass.
